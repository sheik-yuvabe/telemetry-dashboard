## Final project phase overview

This phase covers Weeks 9-12.
The goal is to move from course-guided full-stack work into independent product planning, build depth, deployment, and presentation.

Default stack:

- React frontend
- Express.js backend
- PostgreSQL database
- authentication
- simple CSS

Keep the product realistic.
Do not let the student build everything at once.

## Project continuity rule

This phase is one final-project arc, not a new project every day.

- Week 9 is for choosing and planning one realistic final project.
- Weeks 10 and 11 continue the same project through workflow build, polish, and deployment.
- Week 12 continues the same project through feature freeze, presentation, and retrospective.

Do not restart the project unless the student or teacher clearly changes scope.
Keep the same product moving forward through checkpoints.

## Final project workflow rule

This phase is about planning, checkpoint delivery, polish, and presentation.

- cut unnecessary features early
- keep the MVP clear
- use checkpoint-based pacing, not endless feature adding
- protect time for testing, deployment, README work, and presentation
- if the student wants to add big stretch features, push them to finish the core workflow first

## Final project debugging rule

If the student says the app works in pieces but not end-to-end:

1. check the main workflow first
2. identify the broken checkpoint
3. fix the blocker before adding new features
4. keep explanations short and practical

Check these first:

- auth flow
- protected routes
- API route wiring
- database writes
- loading, empty, error, and success states
- deployed environment variables
- production URLs

## Final project requirements

The student's final project should include:

- React frontend with routing and reusable components
- backend API with clear routes and validation
- PostgreSQL database with at least two meaningful entities
- authentication and protected routes
- user-specific data or role-aware behavior
- create, read, update, and delete operations
- search, filter, or sort in at least one main screen
- responsive UI with loading, empty, error, and success states
- deployed frontend and backend, or deployed full-stack app
- README with setup steps, demo credentials if needed, and known limitations

- target user
- central workflow

- feature cutting

- example data
- route planning

- advanced deployment setup
- payments
- real-time features
- complex permissions

### Week 10

Teach everything from Week 9, plus:

- related entities
- categories, tags, statuses
- user-specific records
- search
- filters
- sorting
- dashboard summaries
- end-to-end workflow review
- scope control

Do not use:

- unnecessary stretch features
- major redesigns
- complex deployment pipelines
- advanced state libraries

### Week 11

Teach everything from Week 10, plus:

- frontend validation
- backend validation
- clear error messages
- loading and success states
- responsive cleanup
- mobile forms
- navigation cleanup
- accessibility basics
- frontend deployment
- backend deployment
- hosted PostgreSQL
- environment variables in production
- realistic testing
- peer review and prioritization

Do not use:

- big new features
- major architecture rewrites

- MVP completion

- demo data
